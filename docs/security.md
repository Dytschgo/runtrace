# Security

Default policy is redacted_only, intentionally safer than retaining full source conversations. Pattern redaction precedes persistence. Tool argument/result JSON is redacted at string leaves and sensitive fields before serialization; numeric, boolean, object and array values under explicit credential fields are redacted too, while nulls and numerical token counters retain their meaning. Coverage includes provider API keys, GitHub tokens, AWS IDs, bearer credentials, JWTs, secret assignments, connection strings, private-key blocks, local user paths and long high-entropy atoms. No finite pattern set guarantees removal of arbitrary personal information or every secret. Prefer metadata_only for sensitive projects.

`full_encrypted` uses RustCrypto XChaCha20-Poly1305 with random 24-byte nonces. A 256-bit installation key is stored through keyring in the OS credential store. `t3ui init` creates it only for opt-in encrypted capture. Failure to obtain the key aborts capture. Wrong-key decryption is tested. Ciphertext never reaches HTTP or MCP; there is no full-content authorization route in this version. Default MCP scopes are effectively aggregate, metadata and redacted content. Administrative MCP actions are absent.

Policies: full_encrypted < redacted_only < metadata_only < disabled. Application and project policies combine by most restrictive. Per-instance policy uses separate configuration. No browser local storage, external fonts, remote analytics or source credentials are used. Logs omit captured text. Imported source database is opened read-only and never migrated.

HTTP binds loopback only, validates Host and rejects foreign Origin. Non-loopback binding fails startup. This does not defend against malicious processes under the same OS user; stdio MCP clients share that trust boundary. No SQL execution interface exists. Queries are parameterized and bounded. Query timeouts and formal scope negotiation remain limitations.

Purge removes live records and event revisions and writes persistent tombstones preventing reimport. Event-only archives have no content but may retain identifiers. Existing archive bytes are not rewritten. A fsynced installation purge ledger precedes deletion and is replayed on startup/restore. Its path is anchored to the configured installation before T3UI_DB overrides; storage.purge_ledger_path can set an explicit shared path. Keep the current ledger with cross-installation backups and restores. Backups and exported files require separate deletion. Purge is logical, not forensic erasure of storage sectors or old database pages. Do not describe it as cryptographic erasure.
