# Known limitations

The local installation is usable and tested against real history. The original full product specification is not complete, and this release does not claim a 9.0 score.

## Integration and telemetry

- Collection uses verified read-only T3 SQLite v2 projections. Supported HTTP/WebSocket contracts were inspected, but authenticated transport adapters are not implemented.
- No remote peers were configured in the inspected T3 instance. Explicit consistent offline snapshots can share the analytical database under separate instance IDs. Automatic remote discovery, network authentication, clock-offset measurement and a 24-hour outage test remain unfinished.
- Normalized provider-turn tokens are imported from `turnTokenUsage`. A provider turn is not an individual model call. Requested model is linked through a recorded run; provider turns without that link retain an unknown model. Resolved model, cost, first-token time and native-subagent token breakdowns remain unavailable.
- Historical migrated messages without a terminal run are withheld. Missing historical tools remain partial/unavailable, never an asserted zero. Steering/retry/correction classification is incomplete.
- Just Run It correlation is imported through existing T3 thread IDs when its optional database path is configured. Originating device and submission timestamps are not invented.
- No live provider quota adapter or retained historical quota snapshots are available in this installation. The reset-window primitive distinguishes complete and partial sample coverage; the dashboard explicitly shows no collected quota history. This does not prove T3 cannot expose live limits.

## Storage, privacy and operations

- Native DuckDB stays the hot query store. Complete normalized Parquet snapshots are lossless and restorable; automatic 30-day hot eviction, partitioned cold-query unions and automatic archive content expiry remain unfinished. Snapshots also preserve revision/checkpoint/privacy/tombstone metadata; project-level freshness checkpoints can be regenerated by collection.
- Purging logically deletes live content and records reimport tombstones in an installation-scoped ledger. Existing backup bytes are not rewritten. Keep the latest purge ledger with every restore, including restores on another installation, and remove obsolete external copies where required. Logical deletion is not forensic erasure.
- Default capture is redacted-only. Full encrypted capture is tested but not enabled in production. Pattern/entropy redaction cannot guarantee removal of arbitrary personal information. Use metadata-only for especially sensitive projects.
- Source revision caching depends on update timestamps and terminal state. Same-timestamp source corrections require `import --repair`. Adapter revisions invalidate affected cache entries.
- Large first backfills remain CPU-heavy and have exceeded the 250 MB working-set target. DuckDB's memory budget is not an RSS cap. Normal-mode million-event latency and sustained multi-machine operation remain unmeasured.
- Standalone maintenance needs the service stopped. The launcher is explicit; Windows logon/service installation is not configured.

## API, MCP and dashboard

- API errors distinguish invalid filters, unknown routes, internal failures and memory-budget failures. OpenAPI, query cancellation/timeouts and exhaustive filter/sort coverage remain incomplete. List pages are bounded and stable; some aggregates cap distinct groups at 500.
- Twenty read-only MCP tools share the HTTP query service. Full-content scope fails closed. Some comparison/tree tools expose underlying observations rather than every requested derived metric.
- The dashboard uses real data, URL filters, interactive recorded agent trees and honest coverage. Advanced efficiency proxies, complete machine/environment/status/quality global filters, critical-path highlighting and quota forecasts remain unfinished.
- Tool rankings and per-tool latency aggregates query all matching stored calls. Individual call charts/details and Data Quality content analysis remain bounded scans, with explicit partial coverage. Above 10,000 calls, expanding call content is manual.
- Browser tests cover eleven pages, mobile overflow, axe checks, keyboard paths and actual API numbers. No manual screen-reader audit is claimed.
- Hosted CI, cargo-audit, cargo-deny, nextest and cross-platform keychain operation were not executed here.

These are explicit remaining implementation and validation gaps, not all external T3 blockers. See integration-evidence.md and verification.md for the evidence actually obtained.

Full-dataset investigation (2026-11-06) reproduced intermittent database-memory HTTP 503 responses for 500-tool pages with offset 1500 while collection runs at the normal 512 MB budget. The same seven-request frozen/offline benchmark did not reproduce them. This remains an unresolved query/collection concurrency limitation; migration 004 improves substring search, not bulk-page memory behavior.

The bulk-page memory failure has a verified materialized-ID join fix: the focused old-wide-path regression fails under pressure while the new page succeeds; deployed qualification served 280 alternating preview/full 500-tool requests over three healthy collection cycles without HTTP or collector failures at 512 MB. This is bounded evidence, not a guarantee against every possible allocation failure. Remote/quota and cold-eviction limitations above remain.
