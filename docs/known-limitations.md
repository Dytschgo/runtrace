# Known limitations

The local installation is usable and tested against real history. The original full product specification is not complete, and the current local build does not claim a 9.0 score.

## Integration and telemetry

- Collection uses verified read-only T3 SQLite v2 projections. Supported HTTP/WebSocket contracts were inspected, but authenticated transport adapters are not implemented.
- No remote peers were configured in the inspected T3 instance. Explicit consistent offline snapshots can share the analytical database under separate instance IDs. Automatic remote discovery, network authentication, clock-offset measurement and a 24-hour outage test remain unfinished.
- Normalized provider-turn tokens are imported from `turnTokenUsage`. A provider turn is not an individual model call. Requested model is linked through a recorded run; provider turns without that link retain an unknown model. Resolved model, cost, first-token time and native-subagent token breakdowns remain unavailable.
- Historical migrated messages without a terminal run are withheld. Missing historical tools remain partial/unavailable, never an asserted zero. Explicit run-attempt ordinals now identify extra attempts and steering restarts; provider-internal retries and message-correction intent remain unavailable.
- Just Run It correlation is imported through existing T3 thread IDs when its optional database path is configured. Originating device and submission timestamps are not invented.
- Quota is only as good as its sources. Meta sends no usage numbers for Muse yet, Antigravity and Grok history starts when Runtrace first checks them, and a window is complete only when T3 (or the agent) was read at least every 20 minutes across it. Partial windows expose their gaps; sleep is attributed only to recorded observer power events. Native Windows alerts pass threshold/restart/config-off checks. A crash between durable claim and OS display can lose a warning; claims are not repeated.

## Storage, privacy and operations

- Native DuckDB stays the hot query store. Collection checks hourly for 30-day eviction into registered Parquet segments. Hot/cold API equality, concurrent readers, interruption recovery and post-move snapshot restore pass synthetic regressions. Full-history cold queries pass seeded 500-request mixed workloads during advancing collection with zero 503s. Complete full-source and older-backup snapshot restores match every stored column; first-import memory qualification remains open. Cold content expiry and purges hide logical content. Caught publication failures attempt rollback, then check every attempt-owned file against the committed manifest in a fresh transaction before cleanup. A real WAL-creation failure and an error after successful commit have regression coverage; registered files and files whose state cannot be established are retained. Old immutable file bytes and cleanup after process termination still need explicit file lifecycle handling. Snapshots preserve revision/checkpoint/privacy/tombstone metadata and quota history; project-level freshness checkpoints can be regenerated by collection.
- Purging logically deletes live content and records reimport tombstones in an installation-scoped ledger. Existing backup bytes are not rewritten. Keep the latest purge ledger with every restore, including restores on another installation, and remove obsolete external copies where required. Logical deletion is not forensic erasure.
- Default capture is redacted-only. Full encrypted capture is tested but not enabled in production. Pattern/entropy redaction cannot guarantee removal of arbitrary personal information. Use metadata-only for especially sensitive projects.
- Source revision caching depends on update timestamps and terminal state. Same-timestamp source corrections require `import --repair`. Adapter revisions invalidate affected cache entries.
- Large first backfills remain CPU-heavy. No first full frozen-history import has completed under the 400 MB process-memory ceiling. The bounded segment-heap attempt peaks at 328.339 MB but fails native database allocations with only 27/36 projects synced; no mixed requests run. The prior default-heap candidate was stopped at 401.560 MB. Lower partial-run memory does not establish a whole-import limit; DuckDB's budget is not a working-set cap. Memory tuning stops after the bounded retry, per the user's instruction. Full measurements and rejected experiments are in hill-climb-20261118.md. Normal-mode million-event latency and sustained multi-machine operation remain unmeasured.
- Standalone maintenance needs the service stopped. The installed qualified build uses supervised `start`, and intentional `stop` disables recovery. Exact installed logon startup is registered and its one-shot observer is armed, but a real new logon/reboot remains unqualified; the user defers that cycle. The live Tailscale link now forwards directly, with its relay stopped.

## API, MCP and dashboard

- API errors distinguish invalid filters, unknown routes, internal failures and memory-budget failures. OpenAPI, query cancellation/timeouts and exhaustive filter/sort coverage remain incomplete. List pages are bounded and stable; some aggregates cap distinct groups at 500.
- Twenty read-only MCP tools share the HTTP query service. Full-content scope fails closed. Some comparison/tree tools expose underlying observations rather than every requested derived metric.
- The dashboard uses real data, URL filters, interactive recorded agent trees and honest coverage. Observed tool-call/turn and retry/thread ratios expose their coverage. Machine and containing-run status are global URL filters; quota, physical file figures and collection reports remain visible with explicit installation-wide scope labels when attribution is unavailable. Combined-machine trees and thread-token totals use machine-scoped identities and pass duplicate-source-ID regressions. Observed critical-path highlighting uses explicit timed delegation chains, reports timing coverage, and does not infer unrecorded parent waits or sibling dependencies. Environment/quality filters remain unfinished. Pace projections have two real past-window holdout checks (4 and 15.924 percentage-point errors in the current check); this is not general forecast accuracy. Observer sleep attribution has synthetic end-to-end coverage; an actual sleep/resume cycle has not been qualified.
- Tool rankings and per-tool latency aggregates query all matching stored calls. Individual call charts/details and Data Quality content analysis remain bounded scans, with explicit partial coverage. Above 10,000 calls, expanding call content is manual.
- Browser tests cover all thirteen navigation pages plus story journeys, mobile overflow, axe checks, keyboard paths and actual API numbers. No manual screen-reader audit is claimed.
- Hosted CI, cargo-audit, cargo-deny, nextest and cross-platform keychain operation were not executed here.
- The latest full npm audit, including development dependencies, reports zero vulnerabilities. This is the current registry audit result, not a guarantee against future advisories.

These are explicit remaining implementation and validation gaps, not all external T3 blockers. See integration-evidence.md and verification.md for the evidence actually obtained.

The bulk-page memory failure has a verified materialized-ID join fix: the focused old-wide-path regression fails under pressure while the new page succeeds; deployed qualification served 280 alternating preview/full 500-tool requests over three healthy collection cycles without HTTP or collector failures at 512 MB. This is bounded evidence, not a guarantee against every possible allocation failure. Remote/quota and full-history cold-storage qualifications above remain.
